# Local HAR MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution or superpowers:subagent-driven-development if the user chooses delegation. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Consultar y comparar HAR locales desde MCP sin navegador y sin confundir compras con giros o modificadores.

**Architecture:** Núcleo offline independiente del transporte, con almacén de capturas e índices estables. Adaptador especializado de Pragmatic y consultas genéricas para otros proveedores. Servidor stdio y plugin local sobre el mismo núcleo.

**Tech Stack:** Node.js >=22, ESM, node:test, SDK oficial MCP y Zod compatibles; fijar versiones verificadas al implementar.

**Spec:** [Diseño aprobado](../../har-mcp-design.md).

## Global Constraints

- No iniciar Electron, navegadores ni peticiones HTTP durante el análisis.
- No modificar ni borrar los HAR originales ni publicar sus credenciales.
- Hasta ocho archivos abiertos, máximo 256 MiB por archivo.
- Paginación: 50 entradas por defecto, máximo 200; fragmentos de cuerpo hasta 16 KiB.
- Normalizar JSON, formularios, query strings y base64; conservar incertidumbre y referencias originales.
- Todas las salidas comparten sanitización; stdout exclusivo del protocolo MCP.
- Sin excepciones por título ni certificación universal de funciones.
- Conservar el explorador HardFire existente.

## Review Focus

- UTF-8 con BOM y rutas Windows con espacios: cargar sin alterar el archivo (tarea 1).
- Secretos anidados y query strings dentro de texto: ocultarlos en todas las vistas (tarea 1).
- Referencias a cuerpos cíclicas o con hash incorrecto: advertir, no interpretar datos corruptos (tarea 1).
- Varias sesiones o juegos en una captura: no mezclar inventario y ejecución (tarea 2).
- Captura sin inicialización y respuestas fallidas: conservar DESCONOCIDO y no certificar ejecución (tarea 2).

### Task 1: Almacén y consultas seguras

**Files:** Crear `har/store.js`, `har/normalize.js`, `har/sanitize.js`, `test/har-store.test.js`, `test/har-sanitize.test.js`.

**Interfaces:**
- `HarStore({maxFiles=8,maxBytes=268435456}={})`: `open(path) -> Promise<Summary>`, `get(id) -> Capture`, `close(id) -> {closed}`.
- Capture: `{id,entries,warnings}`; índices originales, sin ordenar ni eliminar entradas.
- `normalizeExchange(capture,index) -> {request,response,warnings}`.
- `sanitize(value) -> value` sin mutar el original.
- `listEntries(capture,{filters={},offset=0,limit=50}={}) -> {total,offset,limit,items}`.
- `readExchange(capture,index,{section='both',offset=0,limit=16384}={}) -> {entry_index,request,response,warnings,truncated}`.

### Task 2: Evidencia y comparación

**Files:** Crear `har/features.js`, `har/pragmatic.js`, `har/compare.js`, `test/har-features.test.js`, `test/har-compare.test.js`. Reutilizar primitivas de `providers/pragmatic/session.js` solo si no requieren cargar el runtime del navegador; extraer parser puro a archivo compartido si corresponde y conservar sus pruebas existentes.

**Interfaces:**
- Consumes: Capture y `normalizeExchange(capture,index)` de tarea 1.
- `analyzeFeatures(capture) -> {groups,warnings}`; grupos por proveedor, juego y sesión demostrables, inventario anunciado y ejecución separados, evidencias con `entry_index` y campo.
- `compareCaptures(left,right) -> {actions,fields,values,examples,warnings,truncated}`; ejemplos limitados y sanitizados. Solo diferencias observadas, sin inferencia causal.
- Estados: `PRESENT`, `ABSENT_EXPLICIT`, `UNKNOWN`; solicitudes sin éxito se etiquetan como intento, no ejecución confirmada.
